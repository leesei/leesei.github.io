## Wallet

[BIP32](https://en.bitcoin.it/wiki/BIP_0032) defined a way to derive different wallet (key pairs) from a single random seed.  
A random seed (128–512 bits) (or seed phrase), generate Master Private Key (`m`) and Master Chain Code (`c`).  
Then, using these two values, you derive an unlimited tree structure of child keys:

`m / purpose' / coin_type' / account' / change / index`

Then an wallet is created with the generated keys according to BIP44, BIP49, BIP84.
This is how wallets like MetaMask, Ledger, Trezor, Trust Wallet derive addresses.

| Standard  | Purpose                             | Address Type              | Example Address   |
| --------- | ----------------------------------- | ------------------------- | ----------------- |
| **BIP32** | HD key tree structure               | N/A (key derivation only) | N/A               |
| **BIP44** | Multi-account, multi-coin structure | Legacy P2PKH              | starts with **1** |
| **BIP49** | Adds SegWit wrapped in P2SH         | P2SH‑P2WPKH               | starts with **3** |
| **BIP84** | Native SegWit                       | Bech32 P2WPKH             | starts with bc1   |

[Seed Phrases, Derivation Paths, Private Keys, Signatures, & Accounts. BIP32, BIP39 & BIP44 - YouTube](https://www.youtube.com/watch?v=NrijkY8jP4I)

Storage The wallet (comprising a tree of key pairs) can be stored:

1. User‑Controlled Storage (user controls the private keys)
   - Software wallet/OS enclave
   - Hardware wallet
   - Air-gapped devices
2. Custodial Wallets (third‑party holds the keys)
   - Crypto exchanges (Binance, Coinbase, OKX)
   - Managed enterprise wallets
   - Cloud key management by service providers
3. Institutional / Enterprise Key Management
   - HSM (Hardware Security Modules)
   - MPC (Multi‑Party Computation) wallets  
     Providers: Fireblocks, Coinbase Custody, Zengo, Safe MPC solutions
   - Threshold signing  
     A form of distributed key control, often used with MPC
4. Decentralized Identity (Self-Sovereign ID)  
   [[decentralized-id]]  
   W3C DID systems (did:ion, did:key, did:web, etc.)  
   User should control the private keys for true self-sovereignty
